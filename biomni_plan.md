  "content": "# ANNITIA Image-Based Survival: 12×15 Grid CNN + DeepHit\n\n## Summary\n\nTranspose each patient's longitudinal biomarker data into a **12×15×3 image tensor**, then train a **tiny CNN** (9,150 parameters) with a **DeepHit competing-risks survival head** to jointly predict hepatic events and all-cause mortality. Run a **3-way ablation** on zero-time event handling, select the best strategy by 5-fold CV, retrain on the full dataset, and submit standalone CNN predictions.\n\n---\n\n## 1. Image Construction\n\n### 1a. Annual time grid\n\n- **Grid**: integer years `t = 0, 1, 2, …, 14` relative to `Age_v1` (T=15 columns).\n- **Coverage**: T=15 covers 96.3% of follow-up times; 4 hepatic and 15 death events beyond T=15 are treated as censored at T=15 during label construction (not during image construction — their biomarker data up to T=15 is still used).\n- **Per-patient grid**: each patient's grid spans `[0, min(floor(time_hep_or_death), 14)]`. Grid points beyond the patient's last observed age are outside the observation window and receive a missingness flag of 0.\n\n### 1b. Biomarker interpolation onto the grid\n\n**Biomarker order (fixed, row index 0–11):**\n\n| Row | Biomarker | Column prefix |\n|-----|-----------|---------------|\n| 0 | FibroScan | `fibs_stiffness_med_BM_1_v` |\n| 1 | FibroTest | `fibrotest_BM_2_v` |\n| 2 | ALT | `alt_v` |\n| 3 | AST | `ast_v` |\n| 4 | GGT | `ggt_v` |\n| 5 | Bilirubin | `bilirubin_v` |\n| 6 | Glucose | `gluc_fast_v` |\n| 7 | Triglycerides | `triglyc_v` |\n| 8 | BMI | `BMI_v` |\n| 9 | Platelets | `plt_v` |\n| 10 | Cholesterol | `chol_v` |\n| 11 | AIxP | `aixp_aix_result_BM_3_v` |\n\n**Interpolation procedure (per biomarker, per patient):**\n\n1. Extract the observed `(age_at_visit, value)` pairs from `{prefix}v1 … {prefix}v22` and the corresponding `Age_v1 … Age_v22` columns.\n2. Convert ages to relative time: `t_obs = Age_vk - Age_v1`.\n3. For each annual grid point `t ∈ {0, 1, …, 14}`:\n   - If `t` falls exactly on an observed visit: use that value directly.\n   - If `t` falls between two observed visits: linear interpolation.\n   - If `t` is before the first observation or after the last observation: mark as **outside window** (missingness flag = 0, value = 0 in channels 0 and 1).\n4. If a patient has only one observation for a biomarker (no interpolation possible): that single value is placed at its grid point; all other grid points are outside-window.\n\n### 1c. Normalisation (fit on train, applied to train and test)\n\n**Per-biomarker robust normalisation:**\n\n- **ALT and GGT** (ratio p99/p50 > 5): apply `log1p` first, then clip to `[log1p(p1), log1p(p99)]`, then min-max scale to `[0, 1]`.\n- **All other biomarkers**: clip to `[p1, p99]` (computed on train), then min-max scale to `[0, 1]`.\n- Percentiles are computed on all non-null values across all visits in the training set.\n- Missing values (outside window) are set to 0 after normalisation; the missingness channel distinguishes them from true zero values.\n\n### 1d. Three-channel encoding\n\nEach patient's image has shape **(3, 12, 15)** — channels-first for PyTorch:\n\n| Channel | Content | Formula |\n|---------|---------|---------|\n| **Ch0** — Values | Normalised biomarker value at each grid point | `x_norm[t]` (0 if outside window) |\n| **Ch1** — Differences | Year-over-year change | `x_norm[t] - x_norm[t-1]` at `t≥1`; 0 at `t=0` and outside window |\n| **Ch2** — Missingness | Observation indicator | 1 if grid point is within observation window and biomarker was observed or interpolated; 0 otherwise |\n\n**Rationale for channel design:** A 3×3 conv kernel spanning 3 biomarker rows × 3 time steps can detect patterns like \"rising FibroScan + rising AST over 3 consecutive years\" — a clinically meaningful fibrosis progression signal. Ch1 makes rate-of-change explicit without requiring the model to learn subtraction. Ch2 prevents the model from treating zero-padding as a true zero measurement.\n\n**Why not GASF/MTF:** Standard GASF/MTF produce a T×T square matrix per series. This is geometrically incompatible with the chosen 12×T grid (12 ≠ T=15). The 3-channel direct encoding preserves the spirit of the approach — encoding temporal dynamics as a 2D image — while being geometrically consistent and interpretable.\n\n---\n\n## 2. DeepHit Label Construction\n\n### 2a. Competing risks formulation\n\nDeepHit models two competing causes simultaneously:\n- **Cause 1**: major hepatic event (`evenements_hepatiques_majeurs == 1`)\n- **Cause 2**: all-cause death (`death == 1`)\n- **Censored**: neither event observed within follow-up\n\nEach patient gets a label tuple `(event_type, event_bin)`:\n- `event_type ∈ {0, 1, 2}` — 0=censored, 1=hepatic, 2=death\n- `event_bin ∈ {0, 1, …, 14}` — which of the 15 annual bins the event/censoring falls in\n\n**Bin assignment:**\n```\nevent_bin = min(floor(time), 14)\n```\nwhere `time = age_at_event - Age_v1` (events) or `last_observed_age - Age_v1` (censored), clipped to `[0.001, ∞)`.\n\n**Patient inclusion:**\n- All 1253 patients are included in the image tensor (both endpoints use the same image).\n- For the hepatic label: all 1253 patients (no NaN in hepatic columns).\n- For the death label: 984 patients with non-NaN `death` column; the 269 with `death=NaN` receive `event_type=0` (censored) for the death cause only.\n- **Joint label**: for each patient, `event_type` is determined by whichever event occurred first. If both occur at the same time (impossible in practice), hepatic takes priority. If neither, `event_type=0`.\n\n### 2b. Zero-time event ablation (3 strategies)\n\n8 hepatic events have `time < 0.5 years` (event age ≈ Age_v1 — likely prevalent cases at baseline):\n\n| Ablation | Strategy | Hepatic events | Notes |\n|----------|----------|----------------|-------|\n| **A** | Drop these 8 patients from training | 39 | Cleanest labels; loses 8 events |\n| **B** | Clip their time to 0.5 years → bin 0 | 47 | Keeps all events; small timing error |\n| **C** | Keep as-is (time=0.001 → bin 0) | 47 | Identical to B in bin assignment; tests whether the clip matters |\n\nAll three ablations use the same CNN architecture and training procedure. The winner is selected by 5-fold CV composite score. The winning strategy is then used to train the final model on the full dataset.\n\n---\n\n## 3. CNN Architecture\n\n### 3a. Architecture (PyTorch)\n\n```\nInput: (batch, 3, 12, 15)   # (channels, biomarkers, time)\n\nBlock 1:\n  Conv2d(in=3, out=16, kernel=3×3, padding=1)\n  BatchNorm2d(16)\n  ReLU\n  Dropout2d(p=0.3)           # spatial dropout on feature maps\n\nBlock 2:\n  Conv2d(in=16, out=32, kernel=3×3, padding=1)\n  BatchNorm2d(32)\n  ReLU\n  Dropout2d(p=0.3)\n\nGlobal Average Pooling → (batch, 32)\n\nFC head:\n  Linear(32 → 64)\n  ReLU\n  Dropout(p=0.5)\n  Linear(64 → 30)            # 30 = T×2 = 15 bins × 2 causes\n  Reshape → (batch, 15, 2)\n  Softmax over the 15 bins per cause (independently)\n```\n\n**Output interpretation:** `output[i, t, k]` = probability that patient `i` experiences cause `k+1` in bin `t`, given they have not experienced any event before bin `t`. This is the cause-specific discrete hazard.\n\n**Total parameters: 9,150** — intentionally minimal given 47 hepatic events (195× parameter-to-event ratio even at this size; regularisation is the primary defence).\n\n**No max-pooling:** The 12×15 input is already small. Max-pooling would reduce spatial dimensions to 6×7 after one layer and 3×3 after two, destroying the temporal structure. Global average pooling after block 2 aggregates spatial information without discarding it prematurely.\n\n### 3b. Regularisation\n\n| Mechanism | Value | Rationale |\n|-----------|-------|-----------|\n| Dropout2d | 0.3 | Drops entire feature map channels; more effective than element-wise for conv layers |\n| Dropout (FC) | 0.5 | Standard for FC layers with few events |\n| L2 weight decay | 1e-3 | Applied to all parameters via AdamW |\n| BatchNorm | after each conv | Stabilises training; acts as mild regulariser |\n| Early stopping | patience=20 epochs | Monitor inner-fold validation loss; restore best weights |\n| No data augmentation | — | Time-series images have no valid augmentation (flipping time axis changes clinical meaning) |\n\n---\n\n## 4. DeepHit Loss Function\n\n### 4a. Negative log-likelihood (NLL) term\n\nFor each patient `i` with `(event_type_i, event_bin_i)`:\n\n```\n# S[i, t, k] = survival probability for cause k up to bin t\n# h[i, t, k] = cause-specific hazard at bin t for cause k (model output)\n\nS[i, t] = product_{s=0}^{t-1} (1 - sum_k h[i, s, k])   # overall survival\n\nIf event_type_i == k (cause k event at bin t_i):\n  L_nll[i] = -log(h[i, t_i, k-1] * S[i, t_i])\n\nIf event_type_i == 0 (censored at bin t_i):\n  L_nll[i] = -log(S[i, t_i])\n```\n\n### 4b. Ranking loss term\n\nDeepHit adds a pairwise ranking loss to directly optimise concordance:\n\n```\nFor each pair (i, j) where patient i has an event at bin t_i\nand patient j is censored or has a later event:\n\nL_rank[i,j] = exp(-(F[i, t_i] - F[j, t_i]) / sigma)\n\nwhere F[i, t] = sum_{s=0}^{t} h[i, s, k]  (cause-specific CIF at bin t)\n```\n\n**Hyperparameters:**\n- `alpha = 0.5` — weight on ranking loss: `L = L_nll + alpha * L_rank`\n- `sigma = 0.1` — temperature in ranking loss exponential\n\n### 4c. Handling the 269 patients with `death=NaN`\n\nThese patients contribute to the hepatic NLL term normally. For the death cause, they are treated as censored at their last observed age — their death hazard contributes to the survival term but not the event term.\n\n---\n\n## 5. Training Procedure\n\n### 5a. Optimiser and schedule\n\n- **Optimiser**: AdamW, `lr=1e-3`, `weight_decay=1e-3`\n- **Schedule**: ReduceLROnPlateau, factor=0.5, patience=10 epochs, monitor validation loss\n- **Max epochs**: 200\n- **Early stopping**: patience=20 epochs on validation composite score (0.7×C_hep + 0.3×C_death)\n- **Batch size**: 64 (full dataset fits in memory; larger batches stabilise BatchNorm)\n\n### 5b. 5-fold cross-validation (ablation evaluation)\n\n- **Stratification**: stratified on hepatic event indicator (ensures each fold has ~8–9 hepatic events)\n- **Folds**: 5 (outer only — no inner loop; hyperparameters are fixed, not tuned)\n- **Per fold**: train on 4 folds, validate on 1 fold; record C_hep, C_death, composite score\n- **Metric**: `0.7 × C_hep + 0.3 × C_death` (matches competition metric)\n- **C-index extraction**: from the cause-specific CIF at the event time — `F_k[i, t_event]` for cause k\n\n**Honest expectation**: with ~9 hepatic events per fold, the 95% CI on C_hep is approximately ±0.28. CV scores will be noisy. The ablation comparison is directional, not definitive.\n\n### 5c. Final model training\n\n- Winner ablation strategy retrained on all 1253 patients (or 1245 if ablation A wins)\n- Same architecture, optimiser, and schedule\n- Training stops at the epoch corresponding to the mean early-stopping epoch across the 5 CV folds (to avoid using the test set for stopping)\n\n---\n\n## 6. Prediction and Submission\n\n### 6a. Risk score extraction\n\nFrom the trained model, for each test patient `i`:\n\n```python\n# Hepatic risk score: cumulative incidence at T=15\nrisk_hepatic[i] = sum_{t=0}^{14} h[i, t, 0] * S[i, t]   # cause-specific CIF\n\n# Death risk score: cumulative incidence at T=15\nrisk_death[i]   = sum_{t=0}^{14} h[i, t, 1] * S[i, t]\n```\n\nHigher CIF = higher risk = correct direction for submission (no negation needed, unlike AFT models).\n\n### 6b.
